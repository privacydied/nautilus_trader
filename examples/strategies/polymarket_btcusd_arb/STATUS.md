The parity test tolerance of 1e-9 confirms our pure-Python binary_call_probability port matches Rust within float precision.

Settlement predictor parity fixtures (settlement_cases.json) were generated by running dump_phase1_fixtures.py against the real arb-bot Rust PySignalEngine (arbcore_rs.PySignalEngine). The expected values are Rust PySignalEngine output — not hand-derived, not Python surrogates. Our Python settlement_predictor.py passes the existing 2 fixture cases with 1e-12 tolerance (exact direction, confidence, score, and contributing signals match). However, these are 2 synthetic warmup+momentum cases — not a comprehensive functional equivalence proof. The Python predictor is a simplified reimplementation that preserves scoring logic but does not replicate every internal detail of PySignalEngine's full observe-evaluate loop. Real-world edge cases in signal composition, warmup ordering, and flush detection may differ between the Python port and the Rust original.

Verdict on parity:
- fair_probability.py: TRUE Rust parity. binary_call_probability matches arbcore_rs.binary_call_probability_py within 1e-9 on all fixture cases (8 cases, including at-strike, near-expiry, zero-volatility).
- settlement_predictor.py: PASSING parity on 2 synthetic fixture cases (1e-12 tolerance). Direction, confidence, score, and contributing signals all match PySignalEngine output. Caveat: only 2 synthetic cases; not comprehensive proof of functional equivalence for all edge cases.
